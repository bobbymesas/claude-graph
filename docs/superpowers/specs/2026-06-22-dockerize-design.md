# Dockerize Claude Graph — Design

**Date:** 2026-06-22
**Goal:** Produce a small, self-contained Docker image that builds the site and serves the static output.

## Context

Claude Graph is a fully static site:

- No npm dependencies — `build.js` uses only Node.js built-ins.
- Build step: `node build.js` compiles `content/nodes/*.md` → `data/nodes-compiled.js`.
- Runtime is plain static files served over HTTP. Fonts and highlight.js load from CDNs.

Runtime files required by the browser:

- `index.html`
- `app.js`
- `styles.css`
- `data/graph.js`
- `data/nodes-compiled.js` (generated by the build)

`content/` is **not** needed at runtime — it is compiled into `data/nodes-compiled.js`.

## Approach: multi-stage build → nginx

### Stage 1 — builder (`node:22-alpine`)

- Set workdir, copy the repo's source in.
- Run `node build.js` to generate `data/nodes-compiled.js`.
- No `npm install` step (no dependencies).

### Stage 2 — runtime (`nginx:1.27-alpine`)

- Copy only the static runtime files from the builder stage into nginx's web root
  (`/usr/share/nginx/html`): `index.html`, `app.js`, `styles.css`, and `data/`.
- Use nginx defaults — no custom `nginx.conf`. ES-module `.js` files receive the correct
  `application/javascript` MIME type from nginx's bundled `mime.types`.
- Serves on port 80.

### Why nginx over a Node static server

- Final image ~25 MB; no Node runtime shipped to production.
- nginx is the standard for static hosting.
- Trade-off: two stages instead of one — which is the point, keeping the shipped image tiny.

## Files added

- `Dockerfile` — the two stages above.
- `.dockerignore` — exclude `.git`, `archive/`, `.vercel`, `docs/`, markdown docs, and
  `content/` (compiled in) so the build context stays small.

## Documentation

- Add a "Docker" section to `README.md` only (no CLAUDE.md change).

## Usage

```bash
docker build -t claude-graph .
docker run -p 8080:80 claude-graph   # → http://localhost:8080
```

## Out of scope (YAGNI)

- Custom `nginx.conf` (gzip / cache headers).
- docker-compose or live-reload dev tooling (production-only goal).
- CI integration.
